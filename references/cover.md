# 封面：核心规范与七步流程

封面是扁平矢量插画，主体画这篇主题的具象形态。Pillow 只负责裁切和叠产品官方图标。图片上的文字不做限定——默认不加，要加就用 Pillow 叠，别让生图模型画。一次只生成 1 张，生成后自己先看一眼再交用户。

## 核心规范（v2，2026-08-11 起）

### 风格：扁平矢量插画，主体贴着主题走

- **不预设任何吉祥物，也不内置任何参考图**。主体画这篇讲的那个东西的具象形态：讲 MCP 就画插头与总线，讲定时任务就画钟面与齿轨，讲多 Agent 就画并行出去的几路。**不要每篇都放同一个卡通形象。**
- **风格延续靠图生图**：调 Agnes 时把该系列最近一张已验收封面用 `--image` 传进去，色调与画风自然接上；**该系列还没有封面时不带 `--image` 走文生图**，prompt 里把风格写全（扁平矢量、满幅、主体居中偏右）。这张验收后就成为该系列的参考图。
- **主体形态二选一**：①**具象物件**（设备、界面卡、图标化的道具）＝默认；
  ②**抽象几何核心 + 主题相关悬浮元素**（中央低多边形几何体 ＋ 环绕的小卡片／图标），主题偏机制、偏抽象时用。
- **⛔ 主体不许出现「别人家的」品牌视觉符号**：定主体前先自问一句「这个形象属不属于**别人**的品牌」，答案是「是」就换掉。
  真实案例：`Trae_01`~`Trae_06` 六张封面全用了那只白色几何鲸鱼，那是 DeepSeek 的 LOGO，整批作废重画。

  ⚠️ 这条禁的是**自己联想**把别家符号画进主体；**用户点名要的某个产品图标照做**（那个产品就是文章主角），但走官方原件 ＋ Pillow 叠，不让模型画（见下节）。

### 色调：与正文主题色一致

排版用的主题色是什么，封面背景/主体就用同色系。从 HTML 中读取主题色（每篇一个，如 `#3B82F6` 蓝 / `#4D6BFE` DeepSeek 蓝 / `#14B8A6` 青）。

### 生成通道：优先 `agnes-multimodal`（免积分，2026-09-15 起）

用户 2026-09-15 定：**凡是要生成图像，一律走 `agnes-multimodal` skill 的脚本**，不用宿主内置生图能力（那些消耗积分）。用户不需要特意说「用 Agnes」。

```bash
python3 <HERMES_HOME>/skills/media/agnes-multimodal/scripts/agnes_image.py "<prompt>" \
  --image "<同系列最新已验收封面.png>" --size 2K --ratio 21:9 --out-dir "<封面目录>"
```

- **21:9（2.333）最贴近 2.35:1**，几乎零裁剪损耗：2K+21:9 = 3136×1344 → 居中裁 3136×1334 → 900×383
- 自证看产物域名 `cos-platform-outputs.agnes-ai.cn`；模型恒为 `agnes-image-2.5-flash`（脚本内写死，不走宿主模型路由）
- 免费额度，封面可多试几版，但默认仍只出 1 张
- 中文 prompt + 中文路径：**用 Python `subprocess` 包一层调用**，避免 Git Bash 传参乱码

### 第三方品牌图标（要放别的产品的 LOGO 时，2026-10-08 H23 起）

用户点名要让封面出现某个产品的图标时（H23：「**封面图片除了主体外，要有 Hermes 的图标和 OpenWebUI 的图标**」）：

- **⛔ 绝不让生图模型画 LOGO**——和中文一样是稳定失败项（形状走样、文字糊成错字）。**一律官方原件 ＋ Pillow 精确叠**。
- **取源优先级**：① 官方品牌页（Open WebUI：`https://docs.openwebui.com/brand`，有 icon／横向 logo／透明版直链）② **官网 favicon ／ 站点 assets**（Hermes Agent：`https://hermes-agent.nousresearch.com/favicon.ico`）③ 素材笔记自带的官方截图里裁。
  ⚠️ **别把「素材里的配图元素」当成官方图标，也别把官网 favicon 当废料**（H23 两个方向的坑都踩过）：我一开始把素材首图 `about_hermes.png` 里的**蓝色徽章**当成了 Hermes 图标，用户纠正「**Hermes的图标不对，应该是一个黑色的女的头像**」——**官网 favicon 就是对的**（黑色女性头像，即 Nous 那个女孩形象），素材图里的徽章只是那篇笔记里的配图元素。
- **低分辨率 favicon 上封面三步**（Hermes 官方 favicon 只有 48×48，且**探遍全站没有更大的**：`apple-touch-icon*`／`favicon.svg`／`icon.svg`／`icon-192/512`／`site.webmanifest` 全 404；站点 assets 里的矢量 `nous-girl.svg` 是「NOUS 字样＋圆角边框＋女孩」的白线黑底图，只能深底用，**反相 ≠ favicon**）：
  ① `alpha<240` 的半透明边缘**先刷白**——favicon 四角是 `RGBA(73,73,73,179)` 这类圆角抗锯齿，直接白底合成得 127 灰，**二值化后变黑角**；
  ② LANCZOS 放大到 384 → **二值化 128**——保留灰度的版本（白场提亮、原样）在纯白 App 块上会**露出一块灰底**，二值化最干净、图标感最强（阈值 165 会吃掉脸部细节）；
  ③ **去孤立小连通域**（<120px 判噪），二值化后常残留 1px 点。
  **别走矢量化**：`vtracer` binary 模式试过更差——48px 输入出多边形色块，4x 平滑输入出灰描边。
- **原件固化**：抠好的图标存 `$WECHAT_HOME/assets/icons/`，命名 `产品名_icon.png`；若要放进白块用，另存一张纯标记 `产品名_mark.png`（透明底）；官方矢量原件（如 `hermes_nous_girl.svg`）一并归档备查。
- **底图必须配合**：图标要占画面左右两侧 → 重出底图，prompt 明写「**主体缩小居中、左右各留三分之一空白**」，否则图标没地方放。
- **叠加脚本**：
  ```bash
  python3 scripts/add_brand_icons.py \
    "<封面.png>" "<输出.png>" \
    --icon "<图标.png>" 155 228 160 tile \
    --icon "<图标2.png>" 745 228 160 tile
  ```
  叠法只有两种，**默认 `tile`**：`tile`＝白色圆角方 App 块（图标等比内嵌，就用这个）／`ring`＝白圆盘垫底（只在图标本身是圆形徽标时才用）。脚本自带投影，参数 `--pad-ratio`（内嵌留白）、`--radius-ratio`（圆角）、`--shadow-*`。**别给用户摆方案让他挑，按上面默认走。**
  ⚠️ **`--pad-ratio` 是全局参数**，两个图标想用不同留白 → **分两趟叠**（先叠一个输出中间文件，再叠第二个）。
- **抠图标坑**：从官方 icon 里抠纯色标记时**别只按亮度阈值**——官方 icon 常带一圈淡灰描边（RGB 很深、**alpha 只有 20**），只按亮度会把描边一起抠进去，放进白块后变成「方中带方」。
  **判据＝亮度 ＋ `alpha>200` 同时成立**。
- **和「主体禁用别人家品牌符号」的关系**：那条禁的是**我自己联想**把别家符号画进主体（Trae 01~06 的鲸鱼＝DeepSeek）；**用户点名要的具体产品图标照做**，因为那产品就是文章主角本身，属于显式例外。

### 尺寸：2.35:1（900x383）

生成时直接要 `--size 2K --ratio 21:9`（2.33:1，跟 2.35:1 几乎一样），再用 `scripts/crop_cover.py` 居中裁到 900x383。裁掉的边很少，主体不容易被切。
**别传 900x383 之类的精确尺寸**，接口给的宽幅比例有限，按 `--ratio` 走最稳。

### 硬性要素（必查）

| 要素 | 要求 |
|------|------|
| 构图 | 满幅，无大片空白 |
| 文字 | **可选，默认不加**。要加就 Pillow 叠，不许写进 prompt 让模型画 |
| 风格 | 扁平矢量插画 |
| 主体 | 主题的具象形态，占画面 60%+，居中偏右 |
| 场景元素 | 主体 + 1-2 个贴合主题的简洁元素，勿堆砌 |

> ⚠️ **图上要字，只能 Pillow 叠，不能写进 prompt**（2026-10-07 H22 实测）：prompt 里写「右下角一行很小的角标文字 AI生成 WORKBUDDY」，
> Agnes 连出两版都是 `AI WORKBUDKE`（「生成」整段丢失 ＋ 尾部被自身边缘裁掉）。H20／H21 的成品也都没有角标。
> - **判据：生图模型画出来的错字，比没有字更糟。**
> - 封面文字**不做硬性限定**，加不加看这篇的偏好；要加就**用 Pillow 直接往图上画字**（`ImageDraw.text` ＋ 一个中文字体，字体放 `$WECHAT_HOME/assets/fonts/`），**绝不交给生图模型**。
> - 同理：**画面里任何文字（含中文标题字）都不要指望 Agnes 画对**；必须出现的文字一律 Pillow 后期叠。

## 工作流程

### Phase 1: 收集信息

从排版完成的上下文中收集：

| 信息 | 来源 | 必填 |
|------|------|------|
| 正文 HTML 路径 | 排版产物 | 是 |
| 文章主题色 | 从 HTML 读取（排版时定的主题色） | 是 |
| 系列归属 | 文件名前缀 / `$WECHAT_HOME/output/公众号文章跟踪表.xlsx` | 是 |
| 文章主题 | 标题 / 正文导读 | 是 |
| 主题序号 NN | 跟踪表里该系列最后一条的序号 +1 | 是 |

### Phase 2: 确定主体与参考图

1. 查该系列是否已有已验收封面（`covers/系列名_*.png`）
2. **有** → 用同系列最新已验收封面作参考图（图生图），色调画风自然接上，可按需加变化（换色调、改单色）
3. **没有** → 不带 `--image` 走文生图，主体按这篇讲的东西定；**这张验收后就是该系列的参考图**，不用另存一份
4. **要出现具体设备／道具时改用文生图**：主题需要画出 NAS、笔记本、服务器这类具体物件，图生图常被参考图带偏、把设备挤掉或画成别的（09-13 Hermes 03 实测）→ 不带参考图，prompt 里详述设备外观
5. **定主体前先查品牌归属**：拿同系列旧封面当参考之前，先确认那个主体不是别家的品牌符号。
   **旧封面本身可能就是错的**（Trae_01~06 全用 DeepSeek 的鲸鱼）——图生图只会把这个错误一路复制下去。
   发现主体有问题要**立刻改文生图换主体**，而不是继续「延续风格」

### Phase 3: 构建生图 prompt

prompt 要素：
- 主体：这篇讲的那个东西的具象形态 + 贴合它的场景（如讲 MCP 就画插头接进一条总线，周围散着几块工具卡）
- 色调：与正文主题色同色系（明确写出色相，如"蓝色调"）
- 扁平矢量插画、满幅构图，**主体居中偏右**，左侧留一片干净背景（要叠产品图标时，左右两侧各留出约三分之一，别让图标压在主体上）
- 场景元素 1-2 个，勿堆砌
- **prompt 里不写任何文字要求**（角标、标题字都不写），要字走 Pillow 叠
- **构图必须落进裁剪安全区**（09-13 教训）：成品要按 2.35:1 居中裁剪，原图上下各被砍掉约 1/3。主角和道具（设备、工具）必须**整体位于画面垂直中带**，prompt 里明写「整体位于画面正中央，不要贴近上边缘或下边缘」。切忌把主角与道具上下叠放或左右拉开——必然有一个被裁掉
- **人脸／面具类道具必须给足正向形容词 + 显式负面清单**（09-17 Hermes 07 教训）：prompt 里只要出现「面具／脸／头套」这类元素，**默认会往诡异、恐怖、傩戏、鬼面方向跑**。必须同时写：①**数量**（「画面中只有一张面具，绝对不能出现多张」——多张面具＝傩戏／鬼面连续感，必吓人）②**风格**（「日系动漫可爱风：大眼睛、微笑弧线、奶油白与粉色、圆润轮廓，萌、有亲和力」）③**负面清单**（「绝对不要恐怖，不要鬼脸、不要骷髅、不要獠牙、不要裂口、不要阴森表情」）④**动作要具体到接触关系**（说「主体捧着一张面具斜贴在自己脸旁边，像正要戴上，面具与脸靠得很近」，不要说「拿着面具」——"拿着"会被画成举在身侧或举一排）

### Phase 4: 生成（一步落名）

> **⚠️ 只生成 1 张**：省积分。**不提备选方案，不问要不要换风格**；不合格就自己重做一张。

用 `--name` 直接落最终文件名，不用生成后再改：

```bash
python3 <HERMES_HOME>/skills/media/agnes-multimodal/scripts/agnes_image.py "<prompt>" \
  --image "<同系列最近一张封面>" --size 2K --ratio 21:9 \
  --out-dir "$WECHAT_HOME/output/covers" --name "<系列>_<NN>_<主题>"
```

接着进 Phase 5 裁到 900x383。

### Phase 5: 裁剪（Pillow）

```bash
python3 \
  scripts/crop_cover.py \
  "<原图.png>" "<输出.png>"
```

脚本居中裁剪到 2.35:1 并缩放为 900x383。Pillow 是本技能唯一的外部依赖，装没装先跑一遍 `scripts/selftest.py`。

### Phase 6: 生成后必查

| 检查项 | 问什么 |
|--------|--------|
| 尺寸 | 输出是 900x383（2.35:1）？ |
| 风格 | 扁平矢量插画，和该系列前几张是一路？ |
| 品牌冲突 | 主体是不是**别人家**的品牌视觉符号（如鲸鱼＝DeepSeek 的 LOGO）？是 → 换主体重做 |
| 主体贴题 | 遮住标题，还看得出这篇讲什么？看不出来就是画得太泛 |
| 色调 | 与正文主题色一致？ |
| 文字 | 图上没有模型画出来的错字？加了字的话是 Pillow 叠的？默认无字不算问题 |
| 主体 | 主体居中占 60%+？ |
| 裁剪安全区 | 主体与道具是否都完整落在 2.35:1 画面内（没被裁掉）？ |
| 恐怖感（道具含人脸时） | 面具／脸是可爱动漫风、张数只有 1 张、表情是笑（不是獠牙／裂口）？ |

### Phase 7: 供用户验收

**生成后先自己 Read 看一眼再交用户**（09-17 修正：本条原写「模型无法读图」已作废，本会话模型可直接读 PNG）。
自查一轮能挡掉「面具太吓人」「主体被裁」这类一眼可见的问题，省用户一轮返工。自己看着别扭 → 直接回 Phase 3 改 prompt 重生成，别把废图递上去。
用户是最终质检：
- 用户满意 → 归档为正式命名 `covers/系列名_NN_主题.png`，删除原始宽幅图
- 用户不满意 → 回到 Phase 3 调整 prompt 重新生成

### Phase 8: 归档命名

- 格式：`系列名_NN_主题简称.png`（如 `Hermes_02_装进NAS.png`）
- **系列名必须与 html 所在的目录名一致**：preflight 就是拿目录名当前缀去 `covers/` 里找封面，对不上会报「没找到封面」
- 多系列并存时加系列名前缀，避免编号冲突

## 异常处理

| 情况 | 处理 |
|------|------|
| Agnes 限流（429） | 隔几分钟重试一次；仍失败就记「待补封面」，别换回宿主生图 |
| 生成风格不对 | 调整 prompt 重试；或换一张更贴的参考图喂 `--image` |
| 裁剪后主体偏移 | 检查参考图主体是否居中；必要时改 prompt 强调"主体居中" |
| 面具／人脸太吓人 | 数量写"只有一张"、风格写"日系动漫可爱风（大眼睛+微笑+奶油白粉配色）"、负面清单写"不要鬼脸/骷髅/獠牙/裂口/阴森"，动作写"捧着斜贴脸旁像要戴上"（详见 Phase 3 最后一条） |
| 系列无参考图 | 不带 `--image` 走文生图，第一篇验收后即成为该系列参考 |
