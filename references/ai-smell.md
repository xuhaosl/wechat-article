# AI 味对照：总纲与六病灶实例

主干里的判据都在这一份的原文里，带正反例对照。拿不准某句话算不算 AI 味时查这里。

## ⭐⭐⭐ 总纲：你要像个知识博主，是个「人」（2026-09-24 20:59 用户定调 · 高于本文件所有细则）

> **用户原话**：「**最主要你得记住，你要去AI化，你要表现的像一个知识博主，是个人，
> 而不是一个罗里吧嗦的AI。**」

**这一句是所有规则的来处。** 下面那些「减法」「用词」「标题」「收尾」全是它的推论——
如果哪条细则和它冲突，**以本总纲为准**。

### 知识博主是什么样的人

一个做了几年、踩过坑、有自己判断的博主。他**在跟一个熟人讲一件事**，不觉得自己在「输出内容」。

| 他是 | 他不是 |
|---|---|
| 讲自己用过的、踩过的 | 复述文档、转述官方说明 |
| 有判断，敢说「我觉得这个设计有问题」 | 中立罗列优缺点 |
| 一句话能说清就一句话 | 怕读者不懂，反复解释三遍 |
| 说人话，用有画面的词 | 用术语和说明书腔 |
| 承认「这个我也不确定」 | 什么都说得很确定，像百科 |
| 节奏有快有慢，句子有长有短 | 每句一样长、每段一样结构 |
| 该展开的地方慢慢讲 | 为了「简洁」把该讲的砍掉 |

### 三条判据（写完对着问）

1. **这一段，是我（一个真人）会跟朋友这么说的吗？**
   如果像新闻稿、像产品说明书、像 Wikipedia → 重写。
2. **我在这段里，有判断 / 有反应吗？还是只在中立转述？**
   只转述 → 加一句自己的判断或反应（但必须是我真做过的，不许编）。
3. **这句话删掉，读者会不会看不懂？**
   不会 → 它是垫话（这是「罗里吧嗦」的来源），删。**但注意：判据是「有没有增量」，不是「有多长」。**

### 「罗里吧嗦的 AI」的七个指纹（出现即是 AI 味，逐条自查）

1. **反复冗余的解释**——判断句后再跟一句解释句；术语下定义；说「官方管这个叫 X」
2. **同义重复**——同一个意思换个说法再讲一遍（「是两回事。……，是两回事」）
3. **替读者安排心态**——「你大概没翻过」「这一条别嫌慢」「你会觉得」「放心」
4. **中立的百科腔**——只罗列事实，没有判断、没有反应、没有取舍
5. **节奏均匀**——每句一样长、每段一样结构，读起来像机器吐出来的
6. **连接词垫话**——说白了／本质上／换句话说／也就是说／其实／值得注意的是
7. **不敢有观点**——什么都说「各有优劣」「视情况而定」，谁读完都没印象

### 反面与正面（同一段内容）

**罗里吧嗦的 AI 版**：
> 技能是一份份文档，存在本地目录里。这里面有什么、从哪来、怎么再装一份新的，你大概一份都没翻过。
> 官方管这个叫渐进披露，名字先给出来，内容按需要展开。你攒一百份技能，也不会把上下文撑爆。
> 这一条别嫌慢，扫一遍比装完再收拾强。

**知识博主版**：
> 技能就是 Agent 的魔法书。她自己干活的时候，会顺手攒成新的魔法写进去。
> 魔法书里有什么、从哪来、怎么再装一份新的，这篇一次说清。

差别不在字数，在**有没有一个真人在说话**。

## 行文减法：一句话只讲一遍，读者体会不许编（最高优先级，2026-09-24 用户第三次纠正）

> **用户原话**：
> 「你以前的行文（包括导语还是正文）都是**罗里吧嗦一大堆，机器人式的做一些反复的冗余的解释**，
> 而读者要的是**通俗易懂**（可以做一些贴近的**类比，但不要多**），**适当点出痛点**，
> 而不是**瞎编一些非读者的体会**。」
>
> **正确顺序：先减，再改词。** 一条意思如果讲了两遍，换成再好的词也没用。
> 本节的优先级**高于**「用词系统」，因为词是给剩下那些句子用的。

### 病灶 A：同义重复（解释完了再解释一遍）

**我的写法**（Hermes 11 实例）：

> 这份清单和工具那张表，是两回事。工具决定她能碰到什么，技能决定她知不知道该怎么碰。

第一句已经把「是两回事」说完了，第二句换个说法又讲一遍。**两句都是解释，读者读到第二句会觉得被当小孩哄。**

**发布版写法**：

> 工具是手，技能是手册。手一直都在，手册得有人写。

**规则**：

- **一个意思只准占一句**。写完立刻回看前一句：如果前一句已经说了同一个判断，删掉后一句。
- **判断句后不跟解释句**。「XX 是 YY」之后**禁止**再写「也就是说…／换句话说…／这意味着…／因为 XX…」。
- **术语不必解释**。技术读者的公众号不解释 API / token / 上下文是什么。术语第一次出现可以直接用，需要时给个类比，不给定义。
- **不要给「官方叫法」**。删掉的典型：「官方管这个叫渐进披露」——读者不需要这个名词，不需要知道它有名字。

### 病灶 B：句子结构自己重复（正说一遍反说一遍）

**我的写法**：

> 她也不是每次干活前把手册从头翻一遍。技能平时只占一行名字，真需要了才把正文读进来。
> 官方管这个叫渐进披露。名字先给出来，内容按需要展开。

**发布版**：只留前两句，到「读进来」就断。

**规则**：

- **「不是 A，而是 B」型**：**全禁**（2026-10-22 用户拍板）。一律改回系动词，不再判断「A 是不是读者会想的东西」——留着这个判断权等于给自己留后门，全库曾积到 35 处 / 27 篇。详见 `bans-4-sentence.md` 第 50 条。
- **「先 X，再 Y」和「不是一上来就 X」选一个**，不要两个都写。
- **同一段里禁止出现两组「因为…所以」**。

### 病灶 C：替读者安排心态（本条最严重）

**用户明确点名**：**不许瞎编非读者的体会**。

**我写的**（全是编的）：

| 我写的 | 问题 |
|---|---|
| 这一条别嫌慢 | 我预设读者会「嫌慢」——他根本没这个反应 |
| 翻起来跟逛应用商店差不多 | 我替读者定义了体验感受 |
| 临时试新东西的时候特别顺手 | 同上，而且是我猜的「顺手」 |
| 这份清单长什么样、开关分别在哪儿改 | 我替读者安排了他关心什么 |

**判据（一句话）**：**这句是读者的「遭遇」，还是我猜的读者的「感受」？**

- **遭遇**（可以写）：又要从头讲一遍／每次都这样／配了半天没生效／昨天刚配好今天又变了／翻遍了菜单没找到
- **感受**（不许写）：别嫌慢／很好用／特别顺手／太香了／你会喜欢／读起来不累／放心

**三禁句式**：

1. 禁「你会觉得 / 你可能觉得 / 你会想 / 你大概」
2. 禁「别嫌 X / 不用担心 / 放心」（替读者做心理建设）
3. 禁把体验感受当卖点（`用起来很顺` / `体验极佳` / `上手很快`）

> **注意区分「痛点」和「体会」**：
> 痛点是**读者自己会说的话**（他对着 AI 抱怨的那句），体会是**我猜他会说的话**。
> 遭遇写，感受删。详见 `references/title-playbook.md` 的硬规律 14/15。

### 病灶 D：瞎编类比（类比可以，但不要多）

**规则**：

- **一篇最多 2 个类比**。超过就是堆砌，读者会觉得在硬凑。
- **类比必须贴差异点**。`工具是手，技能是手册` 好——手和手册正好对应「能碰到」和「知道怎么碰」。
  说「工具像工具箱，技能像说明书」就弱，因为工具箱和说明书没有「能力 vs 知识」的层次差。
- **一个类比讲完就停**，不许追问、不许展开、不许「换句话说」。发布版 `手一直都在，手册得有人写` 是同一个类比的收尾，不是第二个类比。
- **不贴切就换，不是删**（用户原话：「不贴切」＝换比喻不是删）。

### 病灶 E：段落自己会长（长度问题，但**不设字数硬线**）

**实测**：Hermes 11 我写了 30 段正文，其中 14 段是「解释性垫话」，全篇删完反而更清楚。

> ⚠️ **2026-09-24 20:55 用户纠正**：
> 「**字数不要设限，重点是把内容讲清楚、吸引读者**，而不是非得约束在多少字以内。」
> → **不设「每段不超过 N 字」「全篇不超过 N 字」这类硬线。**
> 该讲透的地方讲透，该展开的展开；字数不是目标，**讲清楚 + 留得住人**才是目标。

**真正的判据是「有没有增量」，长度不算**：

- 删一段之前只问一句：**删掉它，读者会看不懂 / 会少知道一件必要的事吗？**
  - 会 → **留着，多长都留**
  - 不会 → 删，它是垫话

**判断「这句是垫话」的四个特征**（不是看长短）：

1. 它没有提供新信息（只是把上一句换个说法）
2. 它是「解释我的解释」（术语定义、「官方管这个叫X」）
3. 它是我猜的读者感受（你会觉得 / 别嫌 / 放心）
4. 它删掉之后，前后两句直接连得上

**反过来说，下面这些情况该长就长，不许为了「简洁」砍**：

- 一段操作步骤，砍了就跟着做不下来
- 一个类比的展开，砍了类比就断了（但整篇类比总数仍受「不要多」约束）
- 一个真实踩坑的细节，砍了可信度就没了
- 必要的背景交代，砍了读者进入不了场景

**动作**：**成稿后单独走一遍减法 pass**——逐段问上面那一句，把答「不会」的删掉。
这个 pass **和写稿分开做**（边写边删，写不下去，也删不干净）。

### 病灶 F：连接词与垫话（原红线的执行强化）

以下词出现即删，**不替换**：

说白了 / 本质上 / 这意味着 / 换句话说 / 也就是说 / 其实 / 总的来说 / 值得注意的是 /
需要说明的是 / 在这里 / 我们可以看到 / 不难发现 / 简单来说 / 打个比方说 / 顺便说一句
