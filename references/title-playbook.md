# 标题打法：五套路、六维、硬规律

完整标题规则。动笔前定标题时按这个出，被否了先回 Step 1 说清知识点再重起。

## 核心定位

你是一个**会学习的标题顾问**，别当自己是"标题生成器"。每次生成标题、用户做出选择后，你会记录这次决策。当未来的数据分析技能告诉你"哪类标题实际效果好"，你的推荐会越来越准。

## 输入

### 必选
- **Markdown 文件路径**：文章源文件（`$WECHAT_HOME/source/` 下的 `.md` 文件）

### 可选（用户提供时使用，缺失时自动推断）
- **系列归属**：Claude Code / CodeX / 独立单篇
- **用户想法**：用户已有标题想法（"我想叫XXX，你帮我看看"）
- **目标情绪**：用户想要的语气（轻松/紧迫/震撼/温暖）

## 工作流程

### 第1步：理解文章

1. 读取 Markdown 文件
2. 提取关键信息：
   - **核心主题**：一句话概括文章讲什么（≤20字）
   - **独特洞见**：这篇文章有什么别人文章里没有的东西？（如果找不到，标注"信息量不足，标题不适合过度承诺"）
   - **目标读者**：谁需要这篇文章？（Claude Code 新手 / 进阶用户 / 所有学AI的人）
   - **情绪基调**：文章是吐槽向/干货向/发现向/对比向？
3. 如果是系列文章，读取同系列前几篇的标题，分析已有套路分布

### 第2步：分析用户已有想法（如有）

如果用户说"我想叫XXX"：
1. 先不生成新标题，先分析用户的想法
2. 用六维体系给用户的想法打分
3. 指出优点和风险
4. 然后再生成5个备选，把用户的想法也纳入横向对比

### 第3步：多套路生成标题

**强制要求**：每个套路至少生成1个标题，总共至少5个，覆盖全部5个套路。

#### 套路1：痛点直击 🔥
用"你"开头，直击读者正在经历的、具体的困扰场景。

公式：`[具体产品/场景] + [具体痛点动词] + ？`
- ✅ "Claude Code装不上看这篇" — 具体场景+结果暗示
- ✅ "CodeX每次生成都报这个错？" — 具体错误+悬念
- ❌ "AI工具使用问题汇总" — 太泛
- ✅ "又要从头讲一遍？" — 读者对着 AI 的真实抱怨，反问处境的写法（2026-09-16 Hermes 06 终稿前半句）
- ❌ "不用再讲第二遍" — **好处声明，不是痛点**（读者只会觉得"挺好"，不会认领自己）。详见硬规律 15

#### 套路2：反常识 🤯
推翻一个约定俗成的认知，或者给出一个读者从没想过的新视角。

公式：`[常见认知] + 其实/根本/不是 + [真相]`
- ✅ "Claude Code其实是个Agent框架" — 纠正一个常见误解
- ✅ "Agent最值钱的能力不是写代码" — 反直觉排序
- ❌ "重新认识Agent框架" — 太模糊，没有颠覆感

#### 套路3：数字量化 📊
N个/倍/分钟，配合具体可衡量的结果。数字让读者大脑自动计算"值不值得花时间"。

公式：`[N个/倍/分钟] + [具体事物] + [预期结果]`
- ✅ "CodeX桌面版5分钟上手" — 时间承诺
- ✅ "改一行配置，生成速度翻3倍" — 投入产出比
- ❌ "提高效率的几个方法" — N不具体

#### 套路4：悬念制造 😱
不说结果，只给一个足够有趣的前提。读者必须点进来才知道答案。

公式：`[一个反常/惊人的前提] + （隐去结论）`
- ✅ "我让CodeX和Claude Code互相写代码" — 想知道结果
- ✅ "把这个配置关了之后，效率反而高了" — 反直觉+悬念
- ❌ "一次有趣的实验" — 太弱，没有具体情节

#### 套路5：价值承诺 🎁
不看是你的损失。要落在"这个信息别处没有"上。"读完这篇能学XX"这种承诺太泛，谁都能许。

公式：`[稀缺信息/方法] + （隐含"只有这里能告诉你"）`
- ✅ "这个MCP配法，文档里没写" — 稀缺信息
- ✅ "Claude Code就该这么玩" — 态度+独家方法
- ❌ "MCP配置教程" — 太像说明书

### 第4步：六维评分

每维 1-5 分，最终加权总分 = Σ(得分 × 权重)。

| 维度 | 权重 | 评分标准 |
|------|------|---------|
| **吸引力** | 30% | 5分：看到就想点，不点难受；3分：有兴趣但可以等等；1分：可点可不点 |
| **准确度** | 25% | 5分：标题是文章核心内容的精准提炼；3分：基本对应但角度偏了；1分：标题党，内容和标题关系不大 |
| **简洁度** | 15% | 5分：≤13字，手机端完整显示；3分：14-16字，可能截断1-2字；1分：≥17字，截断严重 |
| **差异化** | 15% | 5分：同主题下没有类似标题；3分：不算独特但也不烂大街；1分："N个方法""一文读懂"类通用模板 |
| **情绪值** | 10% | 5分：触发强烈好奇/惊讶/共鸣/紧迫；3分：有情绪但不够强烈；1分：平铺直叙像新闻标题 |
| **搜索友好** | 5% | 5分：含核心关键词且自然融入；3分：含关键词但生硬；1分：不含任何可搜索的关键词 |

**得分与标签**：
- ≥90 分：🌟 强烈推荐
- 80-89 分：👍 推荐
- 70-79 分：💡 可用
- 60-69 分：⚠️ 需改进
- <60 分：❌ 不推荐

### 第4.5步：合规风险检查（强制）

> **教训来源**：2026-08-04 首次实战，《我的论文，一半是 AI 写的》得分 90 被推荐，但用户指出该标题有"学术不端"误解风险——他本人是科研作者，此标题会让人误以为用 AI 代写论文，损害学术声誉。**吸引力高 ≠ 无风险。**

六维评分只衡量"吸引力质量"，**不衡量"道德/法律/声誉安全"**。高分标题如果触发合规风险，必须降级处理。

**核心思维：识别风险模式，规则只是它的索引。** 学术不端只是合规风险的一个例子——医疗、金融、教育、法律、职场等领域各有各的"敏感点"。检查时要**举一反三**：这篇文章的读者是谁？标题会不会让他们对作者/内容产生某种危险误解？

**通用检查框架**（对所有文章适用，逐条自问）：

| # | 风险维度 | 自问（通用） | 领域示例（举一反三） |
|---|---------|------------|-------------------|
| 1 | **道德/诚信质疑** 🎭 | 标题是否让人质疑作者在专业领域内的诚信？（暗示违规、造假、钻空子） | 学术→"AI 代写论文"；医疗→"医生教你骗保"；金融→"跟着我避税"；职场→"这样摸鱼不被发现" |
| 2 | **夸大承诺** 📢 | 标题承诺的效果是不是文章根本给不到的？ | 教育→"7天英语母语水平"；健身→"一周瘦20斤"；投资→"稳赚不赔"；技术→"一行代码搞定一切" |
| 3 | **法律红线** ⚖️ | 标题是否暗示违法违规行为？（盗版、绕过限制、无资质从业） | 通用→"免费看全网付费课程"；金融→"无证荐股"；医疗→"祖传偏方治绝症" |
| 4 | **作者声誉** 🛡️ | 标题是否让作者在同行/客户/读者面前难堪或损失信任？（贬损、暴露隐私、立场争议） | 通用→"我前公司烂透了"（指名道姓）；"导师是水货"；"我客户都是韭菜" |
| 5 | **读者不适/误导** 🚫 | 标题是否用焦虑、恐惧、歧视、猎奇绑架读者，或把目标读者吓走？ | 通用→"不学这个你将被淘汰"；"穷人别点进来"；"这个病99%的人都有" |

**领域专项自查**（识别文章主题属于哪个领域，检查该领域的特有敏感点）：

- 🎓 **学术/科研**：标题不得暗示代写、数据造假、抄袭、代发表 → 用"辅助/工作流/工具"替代"代写/写完/全包"
- ⚕️ **医疗/健康**：不得暗示疗效、包治、替代正规治疗 → 用"了解/参考/趋势"替代"根治/治愈/神药"
- 💰 **金融/投资**：不得暗示稳赚、保本、内幕、荐股资质 → 用"思路/案例/复盘"替代"必涨/稳赚/内幕"
- 📚 **教育/学习**：不得暗示速成、包过、保offer → 用"方法/路径/拆解"替代"7天速成/包过/保进"
- 🏢 **职场/管理**：不得暗示违规操作、泄露公司机密、贬损特定群体
- ⚖️ **法律/政策**：不得暗示规避监管、无资质执业、教唆钻空子
- 🧒 **育儿/情感/生活**：不得制造焦虑、恐吓式营销、贩卖年龄/性别焦虑
- 🔬 **技术/工具**：不得暗示 AI 全自动替代人类核心成果、夸大效果上限

**处理规则**：
1. 先做**通用 5 项检查**，再按文章领域做**专项自查**
2. 任一风险触发 → 该标题**不得作为推荐**，即使六维得分最高
3. 在标题下方标注 `🚨 合规风险：<风险维度>` 并给出替代方向（如"改为强调'辅助'而非'代写'"）
4. 如果 5 个标题全部触发风险 → 回到第 3 步重新生成，主动避开风险触发词
5. 报告末尾"避坑提示"中列出本次触发过的风险类型，形成经验沉淀
6. **领域清单可扩展**：遇到新领域的敏感点，主动补充进"领域专项自查"列表，并更新技能更新日志

### 第5步：给出推荐和风险

1. 标明推荐标题（合规风险检查后得分最高的），简述为什么
2. 对每个标题指出**潜在风险**（标题党嫌疑/太硬/和内容匹配度存疑/**合规风险**）
3. 给推荐标题一个微调建议（如"把'设置'改成'配置'更口语化"）
4. 如果是系列文章，标注与同系列已有标题的套路冲突（如"前面3篇都是痛点直击，建议换套路"）

## 特殊场景处理

### 场景A：极技术向内容
内容信息量大但情感素材少（如 MCP 协议细节、Hook 实现原理），强行造痛点标题会显得假。

处理方式：
- 标注 `[内容偏硬]`，主动放弃"悬念制造""情绪值"维度
- 改用"精准定位型"标题，让目标读者一眼认出
- 六维评分时降低"情绪值"的权重预期，提高"准确度"的权重
- 例："MCP的Hook是怎么工作的" — 不炸裂，但对的人会点

### 场景B：用户有标题想法
1. 先独立分析用户的想法（六维打分 + 优缺点）
2. 再生成5个备选
3. 把用户的想法作为第6个，拉入横向对比表
4. 最终推荐时不偏向用户想法也不偏向模型生成，纯靠分数说话

### 场景C：系列文章
1. 读取同系列前几篇文章的 HTML 文件名，提取标题
2. 分析已有标题的套路分布（避免套路重复）
3. 检查用词一致性（"Claude Code"不能某篇缩写成"CC"，除非是刻意风格）
4. 如果前面连续3篇都用同一个套路，主动建议换套路

### 场景D：用户要求迭代
用户选了标题1，说"基于这个再给我3个变体"：
1. 保持核心句式不变
2. 变换关键词（如"配置→设置""3倍→翻倍"）
3. 变换语气（直接 → 设问 → 命令式）
4. 对比分析变体和原版的差异

## 和正文的关系

标题定在动笔之前（SKILL.md Step 2），正文按标题里的知识点选材。

| 约束 | 说明 |
|------|------|
| 情绪要对得上 | 标题说「炸裂」，正文就得够情绪化。撑不住就换标题，不许让标题超载 |
| 知识点要落得下 | 标题承诺的那件事，正文得有一节正面讲，不能只在开头提一句 |
| 排版要装得下 | ≤17 字符 / 显示宽 ≤15，手机上两行以内。`layout-check.py` 的 I 项会量 |

> **已下线（2026-10-20）**：原「自动化任务集成」一节作废——定时任务已于 2026-10-20 全部删除，本技能只在人工写稿时被调用，标题由用户点头，没有「自动选最高分」这条路径。

## 标题避坑清单（每次生成时必须检查）

| 坑 | 说明 | 反例 |
|----|------|------|
| 标题党 | 承诺了文章里根本没有的内容 | "看完秒变AI大神" |
| 太笼统 | 换成任何一个类似文章都可以的标题 | "AI工具使用技巧" |
| 太硬 | 像学术论文标题，吓跑普通读者 | "基于MCP协议的Agent间通信机制研究" |
| 套路撞车 | 系列文章连续用同一个套路 | 第1-5篇全是"XXX看这篇" |
| 缺少关键词 | 微信搜一搜完全搜不到 | "真的太强了"（强的什么？） |
| 自嗨型 | 只有作者自己能懂的梗 | "我们家的猫看了都沉默" |
| 长度超标 | 手机上标题折行，第一屏变成参差的字块 | **>17 字符**，或显示宽 >15（基准《又从头讲一遍？Hermes替你记住》= 17 字符 / 14 宽） |
| 负面暗示 | 让读者觉得"这不适合我" | "如果你不是程序员别看" |
| **道德/诚信质疑** | 标题让人质疑作者在专业领域内的诚信（代写、造假、钻空子、规避规则） | 学术→"我的论文，一半是 AI 写的"；医疗→"这样骗保没人发现"；金融→"跟我避税" |
| **夸大承诺** | "必过""秒会""包教""稳赚""根治"类承诺，读者点进来发现兑现不了 | 教育→"7天英语母语水平"；投资→"稳赚不赔" |
| **法律红线** | 标题暗示盗版、绕过限制、无资质从业等违法暗示 | "免费看全网付费课程"、"无证荐股" |
| **作者声誉** | 标题让作者在同行/客户/读者面前损失信任 | "我前公司烂透了"、"我客户都是韭菜" |
| **焦虑/歧视绑架** | 用焦虑、恐惧、年龄/性别歧视绑架读者 | "不学这个你将被淘汰"、"穷人别点进来" |

### 硬规律（生成标题时必须对照）

1. **反差/悬念是高分地基**（5/5 命中）——没有任何高分标题是平铺直叙的
2. **必须有具体价值锚点**：同是反差，"最被低估**的功能**"（有锚点）225 vs "聊着聊着**把活干了**"（锚点模糊）50，差 4.5 倍——反差要落在一个具体名词上
3. **裸数字教程型不进高分榜**：6步搭好 / 3步教会 / 5分钟上手 均未进入高分样本 → 遇到"N步/N分钟"类选题，主动转成痛点直击或反差表达。**但带具体设备/品牌锚点的数字教程型是例外，用户认可**（见硬规律 9）
4. **否定对比慎用**："不是XX替代品"容易让读者直接划走，除非有更强的第二钩子
5. **推荐期 vs 长尾分开看**：刚发布看点击（反差评价型爆发力强），跑量看稳定（揭秘/稀缺型长尾最好）
6. **同类工具多时，标题必须带系列专属关键词**（2026-08-12 新增）：当同类工具/竞品在号里写过多篇时，标题必须带上本系列的专属关键词，否则读者分不清是哪一款。例：RAGFlow 系列必须含「RAG」三字（"AI知识库"太泛，读者无法区分 RAGFlow 还是 WorkBuddy 资料库）。生成标题时先判断：这个系列有没有"专属关键词"？有就必须嵌入标题
7. **功能介绍类标题用正面锚点，禁否定对比**（2026-08-14 WB10 教训）：介绍产品/工具/功能时，用「协作/灵活/效率」等正面价值锚点，禁用「不是XX」否定对比。读者看功能介绍要的是"它强在哪"，不是"它不是什么"。例：WB 资料库篇原《真不是网盘》被否，最终《拉人拉AI一起来干资料库》（正面锚点=协作）。生成标题时先判断：这是功能介绍类吗？是就避开否定对比，正面说价值
8. **标题杠杆是最大可控变量**（2026-08-14 全量数据）：同系列（WorkBuddy 10 篇）内最高 776 vs 平均 161，杠杆 4.8 倍——标题/选题对阅读量的影响远大于系列选择本身。所有决策里标题是投入产出比最高的一环，公式必须焊死。
9. **具体设备/品牌名是最强锚点，优先于泛观点**（2026-09-10 网络基建07 教训）：用户把《都说IPv6直连好，你家未必用得上》（反常识 94 分，六维最高）换成《2秒教你IPv6直连极空间》（数字教程型）——**「2秒」+「极空间」两个具体锚点 > 一个漂亮的反常识观点**。生成标题时若文章涉及具体设备/软件/品牌，优先把名字塞进标题（读者搜得到、认得出），别用泛化的观点型表达。**系列观点交给副标题和正文承担**（该篇副标题保留「门槛凑不齐，直连也白搭」，标题拉点击 + 副标题立观点）

10. **抽象结果词弱于具体对象锚点**（2026-09-12 Hermes 01 教训）：原标题《Hermes 不用你喂，自己长本事》被用户否决，价值承诺落在"长本事"这个抽象结果上——读者看完不知道具体是什么本事，点开欲望起不来。改成《Hermes 会自己攒技能》后，锚点落到"技能"这个读者能看懂、能自行对比的具体对象（以前是我写 → 现在它自己攒）。生成标题时自问一句：**这个价值承诺，读者能一眼说出"具体是什么"吗？** 答不上来就换成具体名词（技能／配置／记忆／脚本／封面），别停在结果形容词上

11. **锚点之上还得有"钩子外壳"**（2026-09-12 Hermes 01 二次改题）：《Hermes 会自己攒技能》锚点已经够具体（技能），但用户还是判"不够吸引人"——因为它是「它会 X」的属性陈述句，读起来像功能介绍，没有让人停一下的理由。换成《Hermes 干过的活，都攒成了技能》，加了一层意外转化（干活 → 攒技能），拉力立刻不同。**可用的外壳**：①场景转化（A 变成了 B）②拟人悬念（偷偷／悄悄）③情绪反差（我熬夜写的，它自己攒）④设问反转（技能谁写的，它自己）⑤价值评价（最狠的一招）⑥"把"字动作句（把写技能这事接过去了）。**自检句式：标题里有没有一个让人"停一下"的意外？** 没有的话，锚点再准也平淡

12. **用户最终定稿的形态：主语＋「自己 X，自己 Y」双自对仗动作句**（2026-09-12 Hermes 01 定稿复盘）：我连交三版全被否（《Hermes 不用你喂，自己长本事》《Hermes 会自己攒技能》《Hermes 干过的活，都攒成了技能》），用户自己定为 **《Hermes 自己干活，自己攒技能》**。拆这个形态：①主语在场、主谓清晰（Hermes 自己干活）②用**动作词**（干活／攒技能），不是结果描述词③「自己…自己…」对仗，短促有节奏④正好 10 字。**我那三版全是描述式**（这件事做完之后长什么样），用户要的是**动作式**（它此刻在干什么）——描述式像产品介绍，动作式才钩人。生成候选时**必须至少附带一条这个形态的动作式标题**，作为基准项；描述式再好也只是备选

13. **纯小众专名当标题 = 无搜索无标签，必须配「大众场景词」或「领域词」**（2026-09-16 进池排查）：近期 5 篇 Hermes 标题（如《Hermes 装进 Windows，一个 Git 就够》）在算法侧几乎无标签可依——库里没有这个工具的中文内容，搜一搜也没有这个搜索词。**判断方法**：这个工具名在中文互联网有没有搜索量？没有 → 标题不能只放专名，必须补一个大众场景（装在什么设备上／解决什么家庭/办公痛点）或领域词（AI Agent／智能体／模型）。反例对照：软路由、极空间、WorkBuddy、Pi 都有既有认知或搜索基础，所以专名能当锚点；Hermes 这类中文圈新面孔需要"搭桥词"

14. **标题里必须出现「读者自己的痛点」，且后半句不许用文章内部的隐喻**（2026-09-16 Hermes 06 首轮教训）：原拟《Hermes 自己记事，满了自己腾地方》被用户判"不够突出用户痛点"——两个病：①**痛点缺席**：全句在讲"它自己怎么做"，没提读者因此少受什么罪；②**后半是文章内部隐喻**：「腾地方」是正文里的比喻（便利贴写满撕最旧一张），读者在标题里读不出价值，价值承诺落空。**自检两句**：①这个标题里，读者能不能看见"我之前受的罪现在没了"？②如果一句里有比喻词，读者不看正文能不能懂它值什么？答不上就换成痛点直陈。**⚠️ 本条只解决"痛点在场"，不解决"痛点够不够疼"——「够不够疼」见规律 15，两条必须一起过**

15. **痛点的「解除」不是痛点——把好处当痛点是最容易犯的错**（2026-09-16 Hermes 06 二次改题）：按规律 14 改出的《Hermes 自己记住你，不用再讲第二遍》**仍被否**，用户原话"还是不够抓用户痛点"。诊断：「不用再讲第二遍」是**功能好处（痛点的解除）**，不是痛点本身——读者读到它的反应是"这功能挺好"，不是"对，我就是这样"。**判据①：把后半句单独念出来**——
    - 形式是「不用再 X」「省了 X」「不必 X」→ 这是**好处**，读者无感
    - 形式是「又要 X」「每次都 X」「讲到第 N 遍」→ 这才是**处境**，读者认领
    **判据②：痛点句里必须有一个"处境中的你"**——不能只有"记住你"这种宾语位置的"你"。
    **最佳落点：直接引用读者对着 AI 会抱怨的那句话**，反问句最省事。终稿《又要从头讲一遍？Hermes 替你记住》（14 字，前半是读者的抱怨、后半是解法）。
    **自检一句**：这句标题，读者会点头说"对，我就是这样"，还是只会说"挺好"？只会说"挺好"就重写

16. **痛点不止「反复受罪」一种写法，也可以是对 AI 表现的一句否定评价**（2026-09-17 Hermes 07 改题）：我按规律 14/15 交了 4 条候选（《还在写「别客套」？人格自己定》88 / 《AI 每次都客套？写个人格文件》86 / 《嫌它太客套？写个文件治它》84 / 《Hermes 人格自己写，口气自己挑》82），用户一条没用，自己写定 **《AI客气不像人？给她定个人格》**（14 字符 / 13 宽）。拆这版：
    - 前半「AI 客气不像人」是**对 AI 表现的否定评价**，不是「又要 X／每次都 X」的受罪句式，但读者照样点头。**判据与规律 15 相同（读者认不认识领），但句式不限于"读者抱怨的原话"**——一句对 AI 的定性评价（不像人／不带脑子／答非所问）同样有效
    - 主语用 **「AI」而不是产品专名**——覆盖面更大、不设认知门槛。对照规律 13（专名要搭桥）：**换成「AI」等于把桥拆了，直接站到大众词上**，小众专名系列可以偶尔这么打
    - 「定个人格」比「写个人格文件」「改这个文件」更有画面感——读者读得出是在给一个"人"立规矩，工具感被压掉了。**同类：锚点要选能"拟人化"的那个说法**
    - 首次把 Agent 称作 **「她」**：人称一换，**全篇包括正文都要跟着统一**，别标题写「她」、正文写「它」
    - **生成时至少附带一条"AI＋否定评价"型候选**（AI 太客气／AI 记不住事／AI 一板一眼），与规律 12 的双自对仗动作句并列

17. **标题就是要讲的那个知识点，直接写出来（2026-09-24 用户两次定调，优先级最高）**

    用户原话：
    > ①「阅读量主要取决于**是否进入微信推荐的流量池**，因此题目要站在微信公众号官方的角度。」
    > ②「**题目也不是产品名 + 管理类目词，而是直接写出知识点。**」

    **⚠️ 我自己犯的错**：把 Hermes 09/10/11 三篇的形态（`Hermes的会话管理`／`Hermes工具集管理`／`Hermes技能管理`）
    当成了**通则**，提炼出「产品名 + 类目词」这个公式去推荐。**这是把表象当规律。**
    用户指出正解：**标题直接写出这篇的知识点**——上面三篇成立，是因为「会话管理 / 工具集管理 / 技能管理」
    **本身就是知识点**，不是因为它们凑成了「产品名 + 类目词」的形状。

    **正解：标题 = 这篇要教的那个知识点**

    用全系列已发布标题交叉验证这条规律：

    | 标题 | 知识点 |
    |---|---|
    | `Pi Agent 的对话是棵树` | 对话结构是树形 |
    | `一个文件，让 Pi 记住整个项目` | 靠一个文件实现项目记忆 |
    | `切片方法选错，知识库白建` | 切片方法决定知识库成败 |
    | `RAG 不接 API，等于白装` | 不接 API 等于没搭 |
    | `Obsidian 把笔记连成网` | 双向链接把笔记连起来 |
    | `Obsidian 记了却带不走` | 数据可迁移性问题 |
    | `软路由到手第一件事，三步通网` | 新机上手的三步网络配置 |
    | `Hermes的会话管理` | 会话怎么管 |

    **判据（唯一一条）**：把标题给一个没读过的人看，**他能说出「这篇要讲什么」吗？** 说不出就是空壳。

    **因此明确撤回的几条**（都是我上一轮自己加的形式主义）：
    - ❌ 「`产品名 + 类目词` 优先」——形态不是目标，知识点才是
    - ❌ 「生成时类目词候选排第一」——改为按「知识点是否明确」排序
    - ❌ 「无标点、无问号、无反差、无悬念」——**误读**。用户的意思是**别为了吸引人而牺牲知识点**，
      不是禁止标点。反例全在自家号里：`又从头讲一遍？Hermes替你记住`／`AI客气不像人？给她定个人格`／
      `装Docker劝退一半人？这次不踩坑`／`切片方法选错，知识库白建`——**问号、逗号、反问句都用了**，
      前提是**知识点没被表达方式吃掉**。
    - ❌ 「反差 / 悬念 / 双自对仗动作句降为备选」——**一并撤回**。
      这些仍是有效手法（`Pi：极简主义，插件担当`／`WorkBuddy 聊久了就变笨？2 步救回来`），
      只是它们**服务于知识点**，不能盖过知识点。

    **仍然成立的**：
    - 长度 ≤17 字符 且 显示宽 ≤15（中文/全角 1，英数/半角 0.5）
    - 标题里带痛点时，痛点必须是**读者的遭遇**（见硬规律 14/15/16）
    - **机制类 / 管理类主题**（讲结构、讲原理、讲怎么管）→ 优先直白写知识点，不硬造痛点、不造悬念

    **自检两句**：① 读者看标题能说出要学什么吗？② 有没有为了好看把知识点表达糊了？

17.5 **第一步先看素材那一节叫什么，直接拿来当标题**（2026-09-24 Hermes 12 定，**取题的第 0 步**）

    用户原话（当场纠正）：
    > 「**Hermes MCP扩展，你还是没懂题目怎么取。**」

    **背景**：素材 `11 Hermes Agent.md` 里这一节的名字就叫 `# MCP 扩展`。
    我先按硬规律 17「直接写出知识点」推荐了 `HermesMCP管理`，还专门去问用户「你说的`Hermes技能管理`和已发 #11 撞名了怎么办」——
    **全是多余的。** 正解就摆在那里：**素材小节名 + 产品名前缀 = `Hermes MCP扩展`。**

    **为什么我连续错**：我把「直接写出知识点」理解成「**要自己重新措辞，套进某个句式**」——
    因为 08/09/10/11 那四篇恰好长成「产品名＋管理类目词」，我就又把它当成了**要往句式里填**的填空游戏。
    用户要的是**原样把这件事的名字说出来**，我却在找句式填空。

    **硬规则（取题第 0 步，先做这个再想别的）**：

    1. 打开素材，看这一节的小标题叫什么
    2. 小标题前面加上产品名 = 候选标题 A
    3. **候选 A 默认排第一**，除非它长度超标（≤17 字符 / ≤15 宽）或与其他篇撞名
    4. 再考虑要不要出别的候选；能不加就不加

    **判据**：素材给这一节取的名字，就是这篇要讲的**那件事的名字**。
    我把「知识点」翻译成自己的话，反而是给读者加了一层转述。

    **实例**：

    | 素材小节名 | 标题 |
    |---|---|
    | `# MCP 扩展` | `Hermes MCP扩展` |
    | `# 会自己攒技能` | `Hermes会自己攒技能` |
    | `# Skills技能`（用户自定为「技能管理」） | `Hermes技能管理` |

    > ⚠️ 这一条**不是**「回到产品名+类目词」（那条已被硬规律 17 撤回）。
    > 区别在：类目词公式是我**自己造**的抽象模板；这一条是**素材自己给的名字**，是原作者（用户）已经替这篇定好的题。

### 决策动作

- **第 0 步：先看素材这一节的小标题，产品名 + 小节名 直接作为第一条候选**（2026-09-24 v2.6 起，排序第一）
- 生成标题时先问一句：这篇的知识点是什么？先写一条「直接把知识点说清楚」的候选
- 在此基础上再出：价值承诺+反差评价、口语场景反差**各至少 2 个**，否定对比最多 1 个
- 六维评分时：对"数字教程型"标题的吸引力分自动降档（-1）
- 推荐时优先"知识点明确 + 具体价值锚点"，其次是"反差+锚点"、"揭秘/稀缺"
- 功能介绍类文章：推荐标题时标注「🔔 功能介绍类，建议推送前让用户确认标题」（避免推了再改重推）
- **数据样本不落库**（2026-10-20 起）：不再调权重、不再等样本量。套路强弱按下方硬规律走

### 改题信号即时沉淀（2026-08-14 新增，反馈闭环；2026-10-20 起是唯一路径）

标题被否这件事，唯一有价值的动作是**当场把原因变成硬规律**。不落库、不等阅读量、不等数据回填：

1. 每次标题被用户改题后，立即分析「为什么被否」：
   - 被否的标题是什么套路？（否定对比 / 数字教程 / 无价值锚点 / 系列关键词缺失…）
   - 用户换成什么套路？（正面锚点 / 口语场景反差 / 痛点直击…）
2. 如果「被否原因」是可复用的模式（如「功能介绍类用否定对比被否」），**立即沉淀为硬规律**（补进上方清单）
3. **先说清「这篇最该讲的是 X」再重新起**（用户原话「先说清楚再重新起」）——被否时别马上换一个，措辞换三版、知识点还错着就是白换
4. 已沉淀的规律在生成标题时强制生效，避免重复踩同一个坑

## 重要规则

- **绝不编造**：标题中的数字、数据、承诺必须能在文章中找到对应内容
