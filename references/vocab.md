# 用词系统：有画面的词优先

判据一句话：这个词，读者能「看见」东西吗？看不见就换。注意这是提醒表不是替换表，命令、参数、字段名一律不许改写。

## 用词系统：有画面的词 > 准确的词（强制，2026-09-24 用户纠正后新增）

> **用户原话**：「这和文末链接之类的没关系。我指的是**用词，写作的语言**，尤其你比对一下**导语**。」
> **我的病**：我在用**准确的词**，用户在用**有画面的词**。准确 → 读者理解无碍，但心里没反应；
> 有画面 → 读者记得住、愿意转述给朋友。**差别就在这一步。**
> 判据一句话：**这个词，读者能"看见"东西吗？看不见就换。**

### 一、导语实例拆解（Hermes 11《技能管理》）

发布版导语：

> 技能就是 **Agent的魔法书**。Hermes 的进化能力也体现在，自己干活同时还会**自己攒成魔法**，写在她的**魔法书**里。
> 魔法书里有什么、从哪来、怎么再装一份新的，这篇一次说清。

我的初稿：

> **她干活的方法**，会自己攒成一份份**文档**，存在你那台机器上。这里面有什么、从哪来、怎么再装一份新的，**你大概一份都没翻过**。这篇一次说清。

**逐词拆开，四个病灶：**

| # | 我写的 | 用户换的 | 病灶 |
|---|--------|---------|------|
| ① | 干活的方法 | **魔法书** | 「方法」是说明书 / 培训手册词汇，冷、无画面；「魔法书」是童话道具，自带画面与惊奇 |
| ② | 文档 | **魔法**（攒成魔法） | 「文档」是文件管理词汇，把有生命的能力降级成静态文件；「攒成魔法」是能力增长 |
| ③ | 她 | **Hermes**（首句）+ 她 | 导语第一句先用产品名立住，后文再用「她」，读者不迷路 |
| ④ | 你大概一份都没翻过 | **删掉** | 这句在说「你没做功课」，带指责感；换成正向陈述能力 |

**规律提炼**：

- **一个贯穿全篇的比喻，要在导语第一句就立住**（「技能就是 Agent 的魔法书」），
  后面所有表达都从这个比喻里长出来（攒成魔法 / 写在她的魔法书里 / 魔法书里有什么）。
  **先定比喻，再写导语**——不是写完导语再想比喻。
- **同义替换的优先级**：有画面 > 有动作 > 准确。永远不在「画面词」和「准确词」之间选准确词。

### 二、病灶词表（我反复写的「说明书词汇」→ 换成有画面的说法）

| 我老写的（冷·无画面） | 换成（有画面 / 有动作） |
|---|---|
| 方法 / 流程 / 能力 / 功能 | 手艺 / 套路 / 本事 / 招式 |
| 文档 / 文件 / 内容 | 手册 / 魔法书 / 底稿 / 材料 |
| 配置 / 参数 / 设置 | 开关 / 旋钮 / 规矩 / 底子 |
| 执行 / 调用 / 处理 | 跑 / 使唤 / 派它去 / 让它干 |
| 记录 / 存储 / 保存 | 记住 / 攒着 / 留下来 |
| 数据 / 信息 | 账单 / 清单 / 底账 |
| 优化 / 提升 / 改善 | 收窄 / 收紧 / 磨快 |
| 实现 / 完成 / 达到 | 跑通 / 装好 / 落地 / 干完 |

> **注意**：这张表是**提醒表**，不按词硬替换。
> 严禁机械替换——「功能」在很多技术语境下就是准确说法，硬换成「本事」会失真。
> 用它的方式：**写完一段，扫一遍有没有这些词，有就停一下问「这里有没有更有画面的说法」**，没有就留着。

### 三、导语专项红线（每条都要过）

> **⭐⭐ 根因条（2026-09-26 用户第三次否导语 · 读这一节先读它）**：
> **导语写「读者最不知道的那条事实」，写成钩子就偏了。**
>
> 用户三次纠正导语，病灶同源——**我每次都想着「怎么把读者拉进来」**：
> - 第一次（09-24）想拉人 → 用**准确的词**（该用有画面的词）
> - 第二次（09-25）想拉人 → **编场景**（「你让 Hermes 查数据库里昨天的订单」）
> - 第三次（09-26）想拉人 → 写成**卖点腔**（「能当 24 小时不睡的助理」）
>
> **正确姿势：导语讲这件事「本身是什么样」，不讲它「有多好」。**
> - 差的导语通篇是**承诺和感受**（能当…／到点自己动手／就不用惦记了）→ 读者读完全程零新信息
> - 好的导语通篇是**事实和门槛**（她自带四十多种工具／数据库、公司 API 不在里头／网关没起来班表就是摆设）
> - **判据（写完立刻问）：导语里有没有一条读者「读完才知道」的事实？** 一条都没有 → 通篇废话，重写
> - 与第 24 条「信息缺口」同源：**信息缺口承担的是导语的全部职责，当修辞手法用就废了**

> **⭐⭐ 场景可以有，但必须是真的（2026-10-20 用户定 · 第四次纠正导语）**
>
> 用户原话「**不是说不可以有场景，但不能瞎编场景，还描写的自以为是的**」。
> - **可以用的场景**：素材里写了的（照原样）、我自己真做过的（能对外讲的事）。两样都没有，导语里就不出现场景。
> - **不许的**：素材没写、我也没做过，为了画面感临时编的（「你让 Hermes 查数据库里昨天的订单」「你打开面板，看到一排工具」）。
> - **不许「自以为是的描写」**：替读者设想他当时在想什么、会有什么反应、心里是不是「咯噔一下」。读者没说过的话，一句不写。
> - **两个要素都要有**：这篇文章写什么 ＋ 为什么值得看。「为什么值得看」靠「你不知道这件事」，不靠场景烘托、也不靠评价句。缺一个就是残的。
> - **判据**：这一句里的每个细节，我能说出它来自哪儿吗？说不出 → 删。

> **⭐⭐ 配角不许抢戏（2026-09-26 同篇第二次否 · 用户原话）**
> 「**这篇的重点是自动化任务，而不是网关，网关和微信助手前面的文章就已经说过了**，这里只要提一下自动化任务的前提条件是 24 小时的网关，不需要太过深入，**尤其是导语，你看你的导语，让读者误以为你在写网关呢**」
>
> 我把**前提条件**当成了主角：第一版导语三句全在讲网关，01 章还塞了一整块 `hermes gateway install` 命令（4 行）。
> - ⭐ **动笔前先定主角**：这一篇的主角是谁？——写「定时任务」，主角就是**任务**；网关只是它的前提。
> - **配套内容有配额**：前提／依赖／前置条件，**导语里一句、正文里一句**，都不展开。
> - **已发过的内容绝不重讲**：网关在前面篇章讲过，这里连命令块都不该出现。
> - **判据**：把导语里出现最多的那个名词圈出来——**它是标题的主语吗？** 不是 → 配角抢戏，重写。
> - 同源：这条与「取题第 0 步＝素材小节名＋产品名」是一对——**标题取小节名，正文重心也要落在这一节真正的主题上**，不能把该节里的配套细节（前提、依赖、安装步骤）当主角。

- **首句先立主体**：产品名/Hermes/AI 出现在第一句，不要一上来就用「她」——读者还没建立指代关系
- **禁指责读者**：「你大概没看过」「你肯定没配过」「大多数人不知道」——
  这类句子的落点是「你的问题」，读者会防御。**换成正向陈述能力或信息缺口**：
  - 差：`你大概一份都没翻过`
  - 差：`你可能一次都没打开看过`（除非换成疑问句或跟一句解法）
  - 好：`这份清单长什么样、开关分别在哪儿改，这篇一次说清`（只给信息缺口，不评判读者）
- **导语里要有一个能记住的比喻或名词**：读者读完导语，脑子里至少留下一个形象
- **导语不重复正文第一章**：导语只负责给「读完这篇你会拿到什么」，不展开内容

### 四、自检方法（写完导语必做）

1. **画面前**：把导语读一遍，问「我脑子里有画面吗？」——没有就重写
2. **转述测试**：如果读者要跟朋友转述这篇，他会用导语里的哪句话？找不出 → 导语白写
3. **降级扫描**：导语里有没有出现病灶词表里的词？有就换或删
4. **主体测试**：第一句有没有立住主体？读者看完第一句，知不知道在说谁？
5. **指责扫描**：有没有「你不知道 / 你没看过 / 你大概没」这类句式？
6. **事实测试（09-26 新增）**：数一数导语里有几条**读者读完才知道的事实**。0 条 → 通篇是承诺和感受，重写。
7. **卖点扫描（09-26 新增）**：有没有「能当…／就能替你…／让你…／再也不用…／不用惦记了」？——**这些是好处宣告，不是事实**，删掉。
8. **翻译标题扫描（09-26 新增）**：有没有把标题翻译成一句话？——「定时任务」→「到点要办的活她自己动手」，**读者从标题已经知道的信息，不许在导语里再讲一遍**。
9. **同句重复扫描（09-26 新增）**：导语句内有没有重复词？——反例「**到点**要办的活…她**到点**自己动手」。
10. **具体名词扫描（09-26 新增）**：导语里有没有**具体名词**？——「一条条任务」「那个进程」这种抽象词＝没信息；要有「四十多种工具」「搜网页、读文件」「网关」这类抓得住的词。
11. **主角测试（09-26 新增）**：导语里出现最多的那个名词，**是不是标题的主语**？不是 → 配角抢戏（反例：写《定时任务Cron》，导语通篇讲网关）。
12. **状语密度扫描（09-26 新增）**：同一个时间／方式状语全篇出现几次？——反例「到点」出现 **8 次**，压到 3 次。**同一个词超过 3 次就该换说法**（`60 秒扫一次也有代价，任务到点之后…` → `该动的时候可能晚一分钟左右`）。
    - **名词主题词同理（09-28 Hermes 15 新增）**：`皮肤`在 1066 字里出现 **18 次** → 压到 13 次（其中 5 次在标题／章节条／卡标题，**正文散文只剩 4 次**），靠代词与近义词（`外观`／`那套`／`它`）分担。判据：**一个名词在正文里超过 6~8 次，读起来就是复读机。**
    - ⚠️ `layout-check.py` 的 E 项只查 9 字以上 n-gram、E2 只查 6 字短语，**单词级高频一律不报，只能自己数**（命令：把定稿跑一遍词频）。

### 五、这条规则的适用范围

不只是导语。**全篇都要用这套词**：

- 章节标题：`她攒技能这件事，触发条件写得很具体`（有动作）而不是 `技能生成的触发机制`（术语）
- 图注：`▲ 每一行都有来路标记` 而不是 `▲ 技能列表示意图`
- 正文转场：`回头看这张表` 而不是 `综上所述`
- 收尾：`库里再全，也总有它没覆盖到的活` 而不是 `技能库无法覆盖所有场景`

**唯一例外**：命令、参数、字段名、专业术语**不许改写**——技术准确性优先于画面感。
