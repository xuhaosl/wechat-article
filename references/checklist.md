# 排版质量检查清单与衔接细则

24 项强制清单。生成 HTML 后逐项过，缺一项补一项再输出。后半段是标题区、章节衔接、图注、清单卡的具体写法。

### 第 5 步：质量检查清单（强制）

生成 HTML 后，**必须逐项检查下表全部条目**（当前 24 项，**以表格编号为准，不要记数量**——新增项时这里不用改，免得又出现「引导语写 8 项、实际 22 项」这种矛盾）。如有遗漏，补齐后再输出。

| # | 检查项 | 要求 |
|---|--------|------|
| 1 | 标题区视觉元素 | 大 emoji 图标（36px）+ h1 标题 + 副标题（**术语清单式**或**一句话价值式**，见「标题区与章节衔接细则」）+ 彩色分隔线 |
| 2 | 导读卡（无目录 · 2026-09-16 改） | 标题区下方**只有**一个导读卡：色块卡片、**40-150 字 / 2-4 句**（红线 200）、**首句必须是读者亲历过的具体场景**（禁「XX 最大的毛病是…」泛论开场）、**一个场景就够——禁堆同类画面**（两句都说「她不听话」＝啰嗦，2026-09-18 用户二次退回）、**痛点须落到根因**（有哪句回答了「她为什么会这样」）、**痛点排列顺序须与正文章序一致**（导语是正文的缩影：先写第 1 章的痛，再简写后续章节的痛；章序一改导语就得改，2026-09-18 用户三次退回）、精准命中本篇要解决的读者痛点、**与第 1 章不重复**；导读卡之后**直接进第 1 章**——目录框／系列介绍段／「上一篇」钩子卡一律不许出现 |
| 3 | 第一章必须是「读者不知道的东西」 | 包含核心特点卡片 / 概念解释 / 配图等，且**不许是读者已经知道的大道理**（判断法：把第 1 章首段念出来，如果读者会想「这我早知道」→ 整章废掉重写）。实操文第 1 章就是动手，不许拿「先想清楚／为什么／该选哪个」开场 |
| 4 | 配图有图注 | 每张配图下方居中灰色说明，**写"图里能看到什么"**（可加 ▲ 前缀），不写"某某图"；**图注 ≤15 字**（2026-09-17 新增——超了在手机上折成两三行小灰字，比图还抢眼） |
| 5 | 正文 emoji 穿插 | 正文每隔 2-3 段穿插相关 emoji，不只出现在标题和提示框 |
| 6 | 代码块有注释 | 关键命令上方加 `#` 注释（浅灰色 `#6c7086`） |
| 7 | 行内代码统一高亮 | 所有命令/文件名/路径/界面菜单路径统一用彩色背景圆角 `<span>`，无遗漏 |
| 8 | 章节过渡语 | **每章末尾必须有一句把读者推到下一章的话**（设问推／代价反问／转折定调），一句即可，**不能省**——漏掉整篇读起来就是"断"的 |
| 9 | 短钩子章节标题 | **章节小标题 ≤15 字是写作自律，脚本不查**（`T_TITLE_MAX` / `T_TITLE_WIDTH` 只量文章主标题，章节标题不受 17 字符限制）——别把这条读成「章节标题可以随便长」；另三条硬约束：**禁代词**（直接写产品名）、**禁与本章首句重复**、不写文档目录式标题 |
| 10 | 写作风格 | 第一人称 + 短段落节奏；**开场三禁**：禁「在当今AI时代」类宏大开头、禁「我电脑里跑着…」类自述开场、禁「用 AI 用久了，你大概也会摸到一条规律」类泛论开场——第一句必须是「你 + 具体场景 + 具体名词」 |
| 11 | 图片完整性 | 源文件对应章节的所有图片均已嵌入 HTML，一一核对图片清单，不漏图 |
| 12 | 表格完整性 | 源文件中所有表格均已转换（section 卡片），无遗漏行/列；<table> 标签零出现 |
| 13 | 代码块完整性 | 源文件中所有代码块均已保留（<pre>），未降级为纯文字描述；非关键命令可在正文行内提及但原始块不删除 |
| 14 | 关键词标签 | **导读卡之后、第 1 章之前**有关键词药丸（如 #WorkBuddy #CodeX）——不是「正文第一段下方」，索引在正文之前（2026-09-16 结构变更时移过位，本条 2026-10-21 校正），由技能根据文章内容自动总结 3-5 个关键词，用文章主题色卡片样式呈现 |
| 15 | 文末引导关注 | 正文结尾有引导关注文案（欢迎关注/设为星标），用主题色卡片或分隔线区隔（2026-08-14 运营复盘新增：关注转化仅 0.4%，需主动引导） |
| 16 | **章节块级边界**（2026-09-16 新增） | **每章用一个 `<section style="margin:0 0 30px">` 包住**，章内有标题条 + 正文；禁止裸标题直接插在正文流里。全篇**只允许一种**章节标题形态（不许混用色块标题 / 纯文字加粗标题） |
| 17 | **标题层级不打架**（2026-09-16 新增） | 章节标题 17-18px；卡片／小节标题 **≤14px**；全篇禁止出现纯黑 `#1a1a1a` 加粗的"伪章节标题"。自检：`font-size:16px` 及以上且同时 `font-weight:bold` 的元素数，**必须等于章节数** |
| 18 | **正文边距归零**（2026-09-16 新增） | 段落左右 margin 必须为 0（`margin:0 0 14px`），留白交给容器 padding。正则 `<p style="margin:0 [^0]` 命中数必须为 0 |
| 19 | **行文密度**（2026-09-16 新增，2026-10-20 与脚本对齐） | **段落长度不设硬上限**——`T_PARA_MAX` 已撤（99999），判据是「删掉它读者会看不懂吗」，会就多长都留；超 80 字仅提示（`T_PARA_LONG`），全篇允许 3 个（`T_PARA_LONG_ALLOW`）；口水词（其实/然后/而且/也就是说/换句话说/顺便/同时）密度 **≤0.25%**（`T_FILLER_RATE`）；**同一层意思全篇只说一次**；**全篇字数不设限**（`T_WORD_MIN`/`T_WORD_MAX` 已撤，判据同样是「删掉读者会看不懂吗」）。用 `scripts/layout-check.py` 自动跑，**阈值以脚本常量为准** |
| 20 | **页面干净度**（2026-09-16 新增） | ①**浅色底收敛到 1 种**（脚本红线 >3 种报警；功能提示一律「统一底 + 左侧 3px 竖条」，不再各用一色）②**正文灰只许 `#3d3d3d` 一种**，次要文字只用 `#999`（禁 `#475569`/`#666`/`#888`）③**分隔线一律居中短线 60×3**，禁满宽 4px 粗线 ④禁卡片套卡片 ⑤**有色文字色 ≤4 种**（爆款实测 3 种）。见 `references/style-guide.md` 的「页面干净度六条」 |
| 21 | **手机显示友好度**（2026-09-17 新增） | ①**标题 ≤17 字符**（中文字/标点/字母/数字各计 1；同时显示宽 ≤15——中文/全角计 1、英文/数字/半角计 0.5）。基准样本《又从头讲一遍？Hermes替你记住》= 17 字符 / 14 宽，手机上刚好一行 ②**图注 ≤15 字** ③**禁并排双卡**（A vs B 对比改上下堆叠单栏卡）④**卡内并列清单必须一项一行**，禁压进同一个 `<p>` 用 ` · ` 串联（否则像一句长话，读者扫不出有几项）⑤**标题区 → 导读卡留白合计 ≤30px**（标题区 pb 8 + 副标题 mb 0 + 分隔线 mb 14；分隔线容器必须 `font-size:0;line-height:0` 把行盒塌掉）。`layout-check.py` I 项自动量 |
| 22 | **单一真相源 = `.html`**（2026-09-21 新增，2026-10-21 用户改定） | `.html` 是唯一交付物，也是唯一真相源。`.md` 只是写作阶段的过程材料——**html 一出来就删掉**，不要求同名、不保留、不对账（留两份就要同步两份，漂移是自己造出来的）。要改稿：md 还在就改 md 走一遍本技能重出 html；**md 已经没了就直接改 html**，改完跑 `layout-check.py` 验结构（改文字不会破坏排版，这一步是兜底） |
| 23 | **对偶拆分 / 否定绕弯**（2026-10-22 新增，用户点名最讨厌） | 禁把一件事劈成两半再对仗：`各管一摊／各配各的／各管各的／分两头／一头 X 一头发／一个管X一个管Y／一边是X一边是Y／前者…后者／一半…另一半`。禁 `不是 A 而是 B` 和 `不是 A，是 B`，改回系动词。**照用的两种**：`一边看资料一边写`（真同时进行）、`你要做两件事，A、B`（步骤清点）。**判据**：把两个半句的主谓调个个儿，句意还成立＝对偶，删。`preflight.py` 把它写进结论行，措辞「改完再发」——**不是可放过的警告，一处都不留** |
| 24 | **含糊指代 / 疑似劈两半**（第 45 条，中危） | `这块／那块儿／那条路／那一套／一回事／那类／另一种／这一趟／人还是／还是那个`、`是两回事`。这些替换成具体名词能更清楚，但**有正常用法**（「另一种做法是先备份」）——按语境判，不硬删。`preflight.py` 单列「中危提示」，与第 23 项不同档 |

> **第 16~21 项 + 导读卡（H）用脚本自动验，不要靠肉眼**（2026-09-16 起强制）：
> ```bash
> python3 scripts/layout-check.py <文章.html>
> ```
> 退出码 0 = 通过 / 1 = 有警告 / 2 = 有硬错误。**硬错误不为 0 不许出稿**；警告要么修，要么在交付说明里写清为什么不修。
> 脚本还会顺带复查禁用样式（flex/gap、background-color、linear-gradient、`<a href>`、`<table>`、`<ul>`）。
> 2026-09-20 起 **J 项**自动查标签配对（section / p / span / pre 开闭 + `<p>` 嵌套 + 重复闭合）——**任何插过段落的稿子都要跑**，浏览器会自动补全，肉眼看不出来。
> **md 不参与交付**（2026-10-21 用户拍板）：`.md` 是写稿时的过程材料，html 一生成就删掉，
> 不留在产物目录里，也不做任何对账。唯一真相源是 `.html`，改稿直接改 html。
> ⚠️ 两个已知边界：①n-gram 只能抓**字面**重复，"换个说法再讲一遍"（如 Hermes 04 把「它一直开着」用 4 种说法讲 5 遍）机器抓不到，必须人工审；②本脚本是**发稿前标准**，已发布的老文章不回改，拿它去跑老文章必然报错，属正常。

### 系列文章衔接规范

- **不在开头提上一篇**（2026-09-16 起）——开头只有导读卡；承接上篇的话挪到文末，与「下一篇」预告合并写
- 每篇结尾引出下一篇内容预告（"下一篇我们……"）
- 系列标题标记在底部（"X 系列 · 第 N 篇"）
- 不同文章中出现的重复概念介绍直接删除或缩减为一句话引用

### 标题区与章节衔接细则（2026-09-13 由 Pi 系列全 8 篇拆解补充）

**副标题两种写法**（Pi 系列实证，二选一）：
- **术语清单式**：用「/」串起本篇覆盖的概念，给"这篇够专业"的信任感 —— Pi 04「追加指令 / steering / follow-up / 内外层循环」
- **一句话价值式**：把本篇收益压成一句可验证的话 —— Pi 08「跨会话不失忆，规矩写进文件它就一直照做」、Pi 01「工具免费，模型你说了算」

> ⚠️ **副标题也受长度红线管**（2026-09-22 加）：与标题同口径 ≤17 字符 / 显示宽 ≤15（英文·数字·半角计 0.5）。
> 副标题是居中的，**排不下会折行**；且 `layout-check.py` 的 I2 会把它当图注量（脚本已修，但写稿时仍要自己数字符）。
> 命名时先数一遍再落笔——2026-09-22 Git 07 用户写的副标题 23 字符 / 20 宽，缩掉「上的」才勉强接近。
> ⚠️ **含问句的副标题注意**：`？` 占 1 字符，别漏算；中英混排最容易超，`GitHub`＝6 字符／3 宽，不是 1 个词。

**章节衔接三种句式**（每章末尾必挂一句，Pi 01 全篇示范）：
- 设问推：「那它到底小到什么程度？往下看。」「可只有四个工具，够用吗？关键在第四个。」
- 代价反问：「这个思路挺干净的。那代价呢，这么小的内核，真打得过那些功能齐全的？」
- 转折定调：「数字只是结果，真正有意思的是它背后的取舍逻辑。」

**图注写法**：写"这张图里能看到什么"，读者不点开也知道值不值得看 —— Pi 04「▲ 在 PowerShell 属性的选项页里，把 Alt+Enter 对应的全屏快捷键取消掉」，而不是「PowerShell 设置图」

**清单卡（「这几件事记住就行」）**：只装可执行要点——键位、路径、命令、规则；观点复述一律不放（详见 `references/techniques.md` 技法 14／16）

### 排版层减法红线（2026-09-24 用户三次纠正后定稿）

> 用户：「行文罗里吧嗦一大堆，机器人式的反复冗余解释」→ 要**通俗易懂**，**类比不要多**；
> 「不要瞎编非读者的体会」；最后一句：「**字数不要设限**，重点是把内容讲清楚、吸引读者，
> 而不是非得约束在多少字以内」。

**⭐ 不设字数硬线**：每段句数 / 每段字数 / 每章段数 / 全篇净字数**均不设上限**。

**判据换成「增量」**——删掉这段，读者会看不懂 / 会少知道一件必要的事吗？
